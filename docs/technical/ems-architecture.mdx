# EMS — Energy Management System

**Status:** Productie (v5.3.3, cloud-2 primary data path sinds 6 mei 2026)

---

## Overzicht

Het Energy Management System (EMS) stuurt het energieverbruik van een locatie aan — batterij, zonnepanelen en laadpalen — met het theater als prioriteit. Het is fysiek een **Unipi Neuron M203** controller op elke locatie, die via Modbus met omvormers en meters praat.

---

## Data Pad (sinds 6 mei 2026)

De EMS-data loopt via **strm-cloud-2**. De proxy is ingebouwd in de OCPP Core API — geen aparte service.

```
EMS Controller (Unipi, ems-lichtwerk:8090)
    │
    ▼  POST /api/v1/ems/telemetry (elke 5s)
strm-cloud-2 (OCPP Core, poort 8000)
    │
    ├── TimescaleDB — alle historische samples
    ├── Redis Event Bus — voor consumers
    ├── Live proxy — haalt live status van de Unipi
    └── Portaal leest via cloud-2:8004
```

**Waarom naar cloud-2?**
- Het klantportaal (cloud-2:8004) leest EMS-data via `/api/v1/ems/*` — geen extra hop
- Telemetrie wordt direct naar TimescaleDB geschreven
- Één databron in plaats van meerdere proxy's met aparte caches

### Endpoints

| Endpoint | Beschrijving |
|----------|-------------|
| `GET /api/v1/ems/live?site_id={id}` | Live status van de Unipi (realtime proxy) |
| `POST /api/v1/ems/telemetry` | Telemetrie van de EMS-controller |
| `GET /api/v1/ems/daily?site_id={id}&days={n}` | Dagtotalen (zon, batterij, grid) |
| `GET /api/v1/ems/history/hourly` | Uurlijkse data |
| `POST /api/v1/ems/override` | Handmatige override naar de Unipi |
| `POST /api/v1/ems/alert` | Guardian-meldingen → Telegram |

### Fallback

De oude proxy op **internal-1** (100.88.9.16:8084) en **internal-2** (100.96.252.107:8084) blijft draaien als read-only fallback.

## Locatie: Lichtwerk

| Component | Specificatie |
|-----------|-------------|
| Grid meter | Eastron SDM630MCT-TCP (192.168.150.170) |
| Omvormers | 2× Afore AF50K-TH (100kW totaal) |
| Accu | 290 kWh LFP (2× 145 kWh) |
| Zon | 32 kWp, 90 panelen |
| EMS controller | Unipi Neuron M203 (192.168.150.250) |

### Strategie

Damped incremental control — `new_cmd = last_cmd + (-grid_w × 0.3)`, DAMPING=0.3, geen PID.

Beslissingen per uur op basis van:
- Spotprijs (EnergyZero API)
- Zonvoorspelling (Open-Meteo GHI)
- Actieve laadsessie
- Accu-SoC

### 9 Veiligheidslagen

1. Budget calculator (pre-flight clamp)
2. Ramp limiter (max 10 kW/cycle)
3. Data freshness + SoC + temperatuur checks
4. **Guardian** — onafhankelijke 0.5s monitor met eigen Eastron-verbinding
5. Readback verificatie
6. Proof testing (elke 5 min)
7. systemd watchdog (10s timeout)
8. Persistente e-stop (overleeft reboot)
9. Bus recovery na 3 falures
